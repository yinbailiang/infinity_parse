# MEMORY RULE — 记忆管理规则

## 用途

记忆用于**跨会话持久化**有价值的信息。智能体应在对话中积累知识，避免在后续会话中重复询问或重蹈已知错误。

## 存放位置

所有记忆文件一律放入 `.agents/MEMORY/memorys/` 目录。

## 何时写入记忆

以下场景应将信息持久化到记忆：

| 场景 | 示例 |
| --- | --- |
| 用户偏好 | 命名风格、架构偏好、工具选择倾向 |
| 历史决策 | 某方案被否决的原因、选择 A 而非 B 的理由 |
| 已知问题 | 复现过的 bug、规避方式、兼容性坑位 |
| 项目约定 | 未写入静态规则但被反复强调的习惯 |
| 会话总结 | 本次会话的关键产出、未完成的遗留任务 |
| 修正反馈 | 用户纠正过的错误理解或错误做法 |

## 命名规范

```text
memorys/<主题>.md
```

- `<主题>`：简明的英文小写 + 下划线，如 `user_preferences`、`known_pitfalls`
- 一个主题一个文件，避免单文件膨胀
- 优先更新已有文件而非新建

## 生命周期

- **创建**：发现值得记住的信息时立即写入
- **读取**：每次会话开始时浏览 `memorys/` 目录内容
- **更新**：信息变化时修改已有记忆，标注更新原因和时间
- **持久**：跨会话保留，不清除
- **不提交**：`memorys/` 已在 `.gitignore` 中排除（记忆是智能体私有上下文，不应进入仓库）

## 文件格式

```markdown
# <主题>

> 最后更新: YYYY-MM-DD

- 要点 1
- 要点 2
  - 子要点
```

每条记忆应简洁，用要点列表而非长篇叙述。

## 禁止事项

- 禁止将一次性信息写入记忆（应使用 `.agents/TEMP_FILES/tmps/`）
- 禁止在记忆中写入敏感信息（密钥、token 等）
- 禁止清空 `memorys/` 目录（除非用户明确要求）
- 禁止在记忆外（如对话历史）依赖跨会话信息——必须写入 `memorys/` 才能传递到后续会话
